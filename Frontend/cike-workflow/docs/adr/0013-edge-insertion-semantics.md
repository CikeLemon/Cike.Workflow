# ADR 0013: 连接线上插入节点——首出口重接 + 按需下游移位 + 单步撤销

## Status

Accepted

## Context

设计器需要"在两个节点中间插入一个节点"的能力：可编辑模式下悬停真实连线，边中点出现插入按钮，点击弹出浮动菜单（复用活动面板分组，过滤无入口/无出口的 Start 与 End）选定类型后插入。插入不是单纯的"加节点"，而是一组复合编辑：删旧连接、加节点、加两条新连接，且可能还要移动画布腾位。其中两个问题必须拍板：新节点用哪个出口接原目标；以及要不要、按什么集合与量级移动既有节点。

## Decision

- **重接规则**：删除原连接 A→B；新增 A（保留原源端口）→ N、N 的**首个出口**（按节点自身端口声明顺序：If 为 True 在先，Switch 为分支顺序 + Default）→ B。重接结果只由节点端口声明决定，不从被插的边推断意图。
- **按需下游移位**：A、B 现有空隙 ≥ 新节点宽 + 两侧各 40px 边距时不移位；否则将原目标的**结构下游**（删旧边后的旧图上自 B 出发可达、排除能回流到 A 的节点）整体水平右移，移位量 = 目标空隙（新节点宽 + 2×40）− 现有空隙。新节点置于移位后 A、B 中心连线中点。被移节点（含原本无保存位置、靠自动布局兜底者）一律把位置物化写回 metadata。
- **撤销粒度**：删连 + 加节点 + 加两连 + 移位经 `makeBatchCommand` 合成**一个**撤销步。
- **适用范围**：仅可编辑模式的真实连线；只读模式与链式容器的视觉边不出现插入按钮。

## Consequences

- 插入多出口节点（If / Switch / Decision）时其余出口悬空，画布校验**立刻**报"缺少连线"类问题、问题清单自动展开、节点打错误标记——这是预期行为而非 bug；不做补偿连边、不弹额外提示，告知职责归问题清单。
- 移位会批量写入一串节点的位置（含物化原本无保存位置的节点）；撤销须按节点逐一还原（原无保存位置者回到 clear 状态），命令实现需记录每节点 from 值。
- 插入按钮与浮动菜单是纯画布层交互；模型层只感知一条复合命令，undo/redo 与序列化路径不因新入口改变。

## Alternatives Considered

- **所有出口接原目标**：被否。等于替用户把全部分支暂时写向同一目标，插入后的图看似"已接好"，掩盖分支尚待设计的事实；首出口规则让多出口节点的分支缺口显式暴露并与校验体系分工。
- **多出口节点只连 A→N、N→B 留给用户手画**：被否。插入即制造不可达节点，每次插入都先产生校验错误，操作与报错必然成对出现。
- **无条件右移固定量 / 整列（280）**：被否。空隙足够时画布被无谓扰动，用户既有的手工布局被改写。
- **几何列插入（所有 x ≥ B.x 的节点右移）**：被否。视觉上位于右侧的无关分支被裹挟移动，移位集合与"被插队"的结构语义不符。
- **各步独立入栈撤销**：被否。出现"只撤了节点、连线还没恢复"的半态，一个用户意图被拆成多次 Ctrl+Z。

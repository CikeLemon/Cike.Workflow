# ADR 0011: 调试前自动保存

## Status

Accepted

## Context

设计器的"调试"功能对数据库中已持久化的草稿版本行发起执行（`POST /WorkflowInstances/DebugRun/{id}`），而非对设计器内存中的画布状态。用户可能在设计器中有未保存的修改，此时点调试会跑旧内容，构成"所见非所跑"的 UX 陷阱。

## Decision

点击调试按钮时，**先静默自动保存当前画布内容**，保存成功后再弹出输入弹窗、发起 DebugRun。保存失败则中断流程、展示错误，不弹窗。

## Consequences

- 用户心智模型简化：调试 = 跑我当前看到的东西，无需关心保存状态。
- 与"发布"语义同源：发布也是一次性提交画布内容，不要求先手动保存。
- 已发布版本（readonly 模式）下调试按钮禁用，自动保存逻辑不会触发。
- 自动保存可能产生用户未预期的版本派生（已发布最新版本保存会 fork 新草稿），但调试按钮在已发布版本下本就禁用，此路径不可达。

## Alternatives Considered

- **检测脏状态拦截**（弹窗让用户选"保存并调试"/"直接调试"）：增加认知负担，且"直接调试旧版本"几乎不是合理意图。
- **强制保存（非静默）**：按钮文字变"保存中…"，视觉噪音大于收益。

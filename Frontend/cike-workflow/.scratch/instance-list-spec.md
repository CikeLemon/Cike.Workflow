# 完善工作流实例列表功能

> 本规格由一轮逐题设计访谈（grilling）收敛而来，术语遵循 `CONTEXT.md`，并受 ADR-0012（实例状态筛选走 `workflowStatuses`，避开 `workflowMainStatuses`）约束。

## Problem Statement

工作空间下的"工作流实例"列表页当前是一个空壳：表格数据是写死的 mock，搜索框和"状态筛选"按钮点了没有任何反应，没有分页，也没有任何加载/空/错误反馈。运维或开发者想回答"这个工作空间里最近跑挂了哪些实例、某个卡住的实例能不能取消、某个工作流的全部运行记录长什么样"这类最基本的问题，页面一个都答不了。

## Solution

把实例列表从 mock 空壳变成真正可用的、按工作空间作用域取数的实况列表：

- 数据来自后端分页查询，按当前工作空间作用域过滤，默认最新创建在前。
- 提供三类彼此正交的筛选：自由文本搜索（搜实例自身字段）、工作流定义筛选（可搜索下拉，锁定"某个工作流的全部实例"）、状态多选 chips（七个运行状态任意组合），外加"只看有异常""显示调试实例"两个开关。
- 表格补齐创建时间列、调试徽标、子流程角标，定义名可点击即按该定义筛选。
- 每行对运行态实例提供"取消"动作，取消是不可撤销的破坏性操作，需二次确认。
- 完整的加载骨架、错误重试、以及区分"无实例"与"筛选无命中"的两种空态。
- 提供手动刷新入口（本期不做实时推送刷新）。

## User Stories

1. 作为运维人员，我想在进入某工作空间的实例列表时自动看到该空间下的实例，以便我不用手动指定范围就只关注这个空间。
2. 作为运维人员，我想让列表默认按创建时间倒序排列，以便最新的运行记录一眼可见。
3. 作为运维人员，我想看到列表分页并显示总条数与当前页/总页数，以便我知道还有多少实例、能翻到更早的记录。
4. 作为运维人员，我想切换每页显示的条数，以便在"一屏看更多"和"逐条细看"之间自行取舍。
5. 作为运维人员，我想用数字页码/上一页/下一页翻页，以便直接跳到某一页而不是无限滚动。
6. 作为开发者，我想用自由文本搜索框按实例名称搜索，以便快速定位某个具名实例。
7. 作为开发者，我想用同一个搜索框按关联 ID 搜索，以便用业务侧的关联标识反查实例。
8. 作为开发者，我想用同一个搜索框按实例 ID 搜索，以便在拿到一个 ID 时直接定位。
9. 作为运维人员，我想让搜索框的占位提示如实说明它能搜什么（实例名称、关联 ID、实例 ID），以便我不会误以为它能按定义名搜索。
10. 作为运维人员，我想用一个可搜索的工作流定义下拉来锁定某个定义，以便只看"这个工作流的全部运行记录"。
11. 作为运维人员，我想在定义下拉里输入定义名的关键字即可过滤候选项，以便在定义很多时快速选中目标。
12. 作为运维人员，我想直接点击表格里某行的定义名就把列表收窄到该定义，以便看到某行后顺手下钻而不用回到下拉。
13. 作为运维人员，我想用一排状态 chips 多选任意状态组合，以便同时查看"已故障 + 已挂起"这类需要一起关注的集合。
14. 作为运维人员，我想让状态 chips 常显全部七个状态并各自带对应配色，以便一眼看清可选词表与当前选中项。
15. 作为运维人员，我想在不选任何状态时看到全部状态的实例，以便"全不选 = 不过滤"符合直觉。
16. 作为运维人员，我想用一个"只看有异常"开关过滤出带异常的实例，以便快速聚焦出过问题的运行。
17. 作为开发者，我想用一个"显示调试实例"开关切换到只看调试（试跑）实例的视图，以便把调试记录和生产运行分开审查。
18. 作为开发者，我想让列表默认隐藏调试实例，以便日常看到的是真实生产运行。
19. 作为运维人员，我想在切换到调试视图时每行都带"调试"徽标，以便始终明确当前看的是试跑记录而非生产运行。
20. 作为运维人员，我想让文本搜索、定义筛选、状态 chips、两个开关这几类条件彼此叠加（AND）生效，以便组合出精确的查询。
21. 作为运维人员，我想在改变任一筛选条件时列表自动回到第一页并重查，以便不会停在超出结果范围的旧页码上。
22. 作为运维人员，我想在表格看到每行的状态徽标，以便一眼判断实例处于哪个运行状态。
23. 作为运维人员，我想在表格看到实例名称（无名时回退显示定义名），以便识别每一条记录。
24. 作为运维人员，我想在表格看到实例执行的定义版本号，以便知道它跑的是哪个版本。
25. 作为运维人员，我想在表格看到关联 ID，以便和业务上下文对应。
26. 作为运维人员，我想在表格看到异常数量（有异常时红色徽标、无异常时占位符），以便快速识别问题实例。
27. 作为运维人员，我想在表格看到创建时间，以便知道实例何时起跑。
28. 作为运维人员，我想在表格看到完成时间（未完成时占位符），以便知道实例何时结束。
29. 作为运维人员，我想让子工作流实例在名称/定义格带一个子流程角标，以便区分它是被别的实例触发的。
30. 作为运维人员，我想点击某行进入该实例的详情页，以便查看它的运行轨迹与节点执行详情。
31. 作为运维人员，我想对运行态（等待中/执行中/已挂起）的实例看到可用的"取消"按钮，以便终止一个卡住或不该继续的实例。
32. 作为运维人员，我想对已终态（已完成/已取消/已故障/已中断）的实例看到禁用或隐藏的取消按钮，以便不会被一个点了也没用的按钮误导。
33. 作为运维人员，我想在点取消后先看到一个点明"取消后无法恢复"的确认弹窗，以便在不可撤销的破坏性操作前有明确的确认点。
34. 作为运维人员，我想在确认取消后看到"取消请求已提交"的提示，并且该行进入"取消中…"临时态，以便知道请求已被接受但状态尚未翻转。
35. 作为运维人员，我想让取消提交后列表自动重查当前页，以便稍后看到实例真实变为已取消，而不是被前端乐观改成一个假状态。
36. 作为运维人员，我想在数据加载时看到与表格列结构对齐的骨架行，以便加载过程布局不跳动。
37. 作为运维人员，我想在加载失败时看到"加载失败"提示和一个重试按钮，以便一键按当前条件重查。
38. 作为运维人员，我想在工作空间尚无任何实例时看到"暂无工作流实例"的空态和引导提示，以便知道这是"还没有运行"而非出错。
39. 作为运维人员，我想在有实例但当前筛选无命中时看到"没有符合筛选条件的实例"的空态和一个"清除筛选"按钮，以便不会误以为一个实例都没有、并能一键复位所有筛选重查。
40. 作为运维人员，我想在工具栏有一个手动刷新按钮，以便在盯着运行中实例时主动重查本页拿到较新状态。
41. 作为开发者，我想让实例列表在后端未提供列表级实时推送时用手动刷新兜底，以便本期不依赖尚未存在的实时通道。

## Implementation Decisions

**作用域与取数**
- 实例列表按工作空间作用域取数：查询请求体直接传当前路由的 `workspaceId`（后端 `WorkflowInstanceFilter` 已支持 `workspaceId`，`WorkflowInstance` 实体自带 `WorkspaceId`）。
- 数据来自分页查询端点 `POST /WorkflowInstances/PagedList?Page=&PageSize=&Sorting=`，请求体为 `WorkflowInstanceFilter`；默认排序采用后端缺省 `CreatedAt desc`；每页默认 20 条；本期不暴露列排序 UI（`Sorting` 参数保留但不做多列排序交互）。
- 分页形态为数字翻页（上一页/下一页 + 页码 + 每页条数 + 总数），刻意偏离仓库既有的"加载更多"无限追加惯例——理由：实例列表是运维排查型（频繁改筛选、需直达某页），追加式在筛选变更时要整段重置、且无法跳页。分页 UI 组件经 `shadcn-vue add pagination` 引入后按需微调，禁止手写 `ui/` 组件。

**筛选（三类正交 + 两个开关，全部 AND 叠加）**
- 自由文本搜索 → 直传 `searchTerm`。后端 `searchTerm` 只匹配 实例名 / correlationId / definitionId / 实例 id / versionId，**不匹配定义名称**；占位提示须如实反映（"搜索实例名称、关联 ID 或实例 ID"）。
- 工作流定义筛选 → 可搜索 combobox（`shadcn-vue add command`），选中项传 `definitionIds`。选项数据源为 `GET /WorkflowDefinitions/OptionList?workspaceId=`，返回 `{ definitionId, name }[]`（跨目录全量）。**不得**用 `Definitions/List` 喂此下拉——它按单个 folderId 严格过滤，无法一次拿到跨目录全量。
- 状态筛选 → 一排可多选 toggle chips（`shadcn-vue add toggle-group`），选中集合传 `workflowStatuses[]`（七态枚举）。**严禁使用 `workflowMainStatuses[]`**（见 ADR-0012：后端 `GetMainStatus()` 未覆盖 `Interrupted`，会抛 `ArgumentOutOfRangeException` 导致潜在 500）。chips 配色沿用现有 `statusConfig`。
- "只看有异常"开关 → `hasIncidents=true`。
- "显示调试实例"开关 → 关（默认）传 `isDebug=false`（只看生产），开传 `isDebug=true`（只看调试）。后端 `IsDebug ??= false` 决定二者不可"生产+调试混看"，故此开关是"切换到调试视图"而非"叠加调试实例"。
- 不单独提供 `isExecuting` 快捷过滤——与状态 chip 的"执行中"重复，避免用户困惑二者关系。
- 任一筛选条件变化 → 页码重置为 1 并重查。

**表格列（左→右）**
- 状态（Badge，`statusConfig` 配色；调试视图下额外挂"调试"徽标）
- 名称 / 定义（实例名做进详情页链接；无名时主显定义名；定义名可点击 → 按该定义筛选；有 `parentWorkflowInstanceId` 时加子流程角标）
- 版本（`v{version}`，等宽）
- 关联 ID（correlationId，等宽、次要色）
- 异常（`incidentCount > 0` 红色 Badge，否则占位符）
- 创建时间（`createdAt`，新增列）
- 完成时间（`finishedAt`，未完成占位符）
- 操作（Cancel）

**行内 Cancel（`POST /WorkflowInstances/Cancel/{id}`）**
- 仅运行态（Pending/Executing/Suspended，即主状态 Running）行可用；已终态行禁用或隐藏。
- 取消不可撤销 → 用 `AlertDialog` 二次确认，文案点明"取消后无法恢复"。（符合项目约定：仅"有撤销兜底"的破坏性操作才免确认，Cancel 无撤销兜底。）
- 后端取消为异步、幂等（非运行态静默忽略）、实例不存在返回 400、返回时状态尚未变更。提交成功后**不做乐观改状态**：给"取消请求已提交"toast，该行标记"取消中…"临时态，随后重查当前页让真实状态回归。
- 本期不做批量取消（后端只有单 id 端点）。

**状态反馈**
- 加载中：与列结构对齐的骨架行（`ui/skeleton`）。
- 加载失败：虚线框"加载失败 + 重试"，重试按当前筛选/页码重查（对齐 `WorkspacesView` 惯例）。
- 空态二分：无任何实例 → "暂无工作流实例" + 引导提示；有实例但筛选无命中 → "没有符合筛选条件的实例" + "清除筛选"按钮（复位搜索/状态/定义/开关并重查）。
- 工具栏手动刷新按钮：按当前条件重查本页（与"取消后重查"复用同一动作）。

**契约同步**
- 实现前须重跑 `node scripts/pull-swagger.mjs` 并重新生成 `src/api/generated`——现有生成客户端尚缺 `PagedList`、`Cancel`、`OptionList` 等函数。判断"后端有无某能力"以重拉后的 swagger 为准，不以现有生成客户端是否存在函数为准。

## Testing Decisions

- **好的测试**：只断言外部可观察行为（composable 暴露的 ref 值与函数调用后的状态变化），不断言组件内部实现细节、不做 DOM 渲染断言。
- **测试缝（唯一，composable 级）**：新增 `useInstancesList(workspaceId)` composable 承载全部决策逻辑——筛选状态、分页状态、`fetch()` 组装 filter body 与 query、`cancel(id)` 后重查、`clearFilters()`、定义选项加载，以及派生判断 `canCancel(status)`、空态二分（无实例 vs 筛选无命中）。`InstancesView.vue` 退化为薄模板绑定，其局部 UI 状态不入测（项目 vitest 为 node 环境、无 @vue/test-utils，组件级不可测）。
- **先例（prior art）**：`src/composables/useInstanceExecution.test.ts` 与 `src/composables/useWorkflowDesigner.test.ts` —— 文件头自述 seam、mock `@/api/generated` 客户端、只断言暴露的 ref 与外部行为。
- **重点覆盖**：
  - `fetch()` 组装的请求体正确携带 `workspaceId`、`searchTerm`、`definitionIds`、`workflowStatuses`、`hasIncidents`、`isDebug`，且**永不**出现 `workflowMainStatuses`（ADR-0012 回归护栏）。
  - 筛选变化 → 页码归 1。
  - `canCancel`：仅 Running 主状态（Pending/Executing/Suspended）为真，其余为假。
  - 空态二分：total=0 且无筛选 → "无实例"；total=0 且有筛选 → "筛选无命中"。
  - `cancel` 成功后触发重查（不做乐观状态改写）。
- **验证门禁**：`pnpm build`（含 vue-tsc 类型检查）+ `pnpm test`（vitest run）。

## Out of Scope

- **列表级实时刷新（原候选 h）**：SignalR 现契约只有 `Watch(instanceId)` 单实例分组推送、无列表级广播；本期用手动刷新 + 分页重查兜底，不引入实时通道。
- **重试 / 删除实例**：后端未开放对应端点，不做入口。
- **批量取消**：后端只有单 id Cancel，且多选+批量属范围膨胀。
- **列排序 UI**：`Sorting` 参数保留但本期不暴露多列排序交互，固定 `CreatedAt desc`。
- **子流程角标点击跳转父实例**：仅做角标标识，不做跳转（跳转会打断列表浏览，且父实例可能在别的筛选下不可见）。
- **"生产 + 调试混看"**：后端 `isDebug` 语义决定不可实现，不在范围内。

## Further Notes

- 受 ADR-0012 约束：任何"只看运行中/只看已结束"的粗粒度分组诉求，都必须在前端把七个枚举展开为对应 `workflowStatuses` 子集，绝不下推到 `workflowMainStatuses`。
- `CONTEXT.md` 已新增/扩展术语：工作流实例的工作空间作用域与主状态分组、子工作流实例、取消（Cancel）。
- 组件引入一律走 `shadcn-vue add`（pagination / command / toggle-group / 以及已存在的 select、skeleton、badge、alert-dialog），禁止手写 `ui/` 组件；图标统一 `@lucide/vue`。

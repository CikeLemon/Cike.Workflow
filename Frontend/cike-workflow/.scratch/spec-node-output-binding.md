

## Problem Statement

工作流设计器里选中一个节点（如 HTTP 请求、`For` / `ForEach` 循环、带结果的通用活动）时，右侧「节点属性」面板能编辑它的**输入（Input）**——每个输入是一个**表达式（Expression）**，可按名字引用**变量（Variable）**。但节点的**输出（Output）**——例如 HTTP 请求的 `statusCode` / `parsedContent` / `responseHeaders`、循环的 `currentValue`、`ActivityWithResult` 的 `result`——在面板上完全不可见、也无法配置。

用户因此无法把一个节点的产出**绑定（Output Binding）**到某个**工作流变量**，让产出值落入该变量、供后续节点读取。要落库这种绑定，目前只能靠手写 wire JSON 或依赖后端默认，设计器里没有任何出口——输出能力对用户是隐形的。

## Solution

在「节点属性」面板的输入区下方新增一个「输出属性」区块，descriptor 驱动地列出该活动类型后端声明的、可浏览的**输出**，每个输出一行：显示名 + 说明 tooltip + 一个**变量下拉**。

用户从下拉里选一个工作流变量，即完成**输出绑定**——把该输出的**内存块引用（MemoryBlockReference）**标识对齐到目标变量的标识（`memoryBlockReference.id = variable.id`）。清除选择即**解绑**，输出回到默认的未绑定状态。已绑定的输出在重新打开面板时按 id 反查、回显对应变量名。

整个区块只负责呈现与写入：不改领域模型、序列化或后端契约；每次变更走既有命令栈（参与 undo/redo 并触发防抖的画布校验）；只读模式（历史版本）下禁用。这与术语表 `CONTEXT.md` 已收录的「输出」「输出绑定」两个概念完全一致——本特性是把既有领域语言实现出来。

## User Stories

1. 作为工作流设计者，我想在选中一个节点时于「节点属性」面板看到它的输出列表，以便知道这个节点能产出哪些值。
2. 作为工作流设计者，我想让输出列表由后端活动描述符（ActivityDescriptor）驱动，以便前端不会写死、始终与后端声明的输出一致。
3. 作为工作流设计者，我想让不可浏览（`isBrowsable=false`）的输出不出现在列表里，以便只看到对我有意义、可配置的输出。
4. 作为工作流设计者，我想在每个输出行看到一个变量下拉，以便把该输出绑定到某个工作流变量。
5. 作为工作流设计者，我想在选中变量后由系统把该输出的内存块引用标识写成变量的标识，以便产出值在运行时落入我指定的变量。
6. 作为工作流设计者，我想让下拉只列出工作流变量（不含工作流输入/输出），以便绑定目标清晰、符合「输出绑定到变量」的语义。
7. 作为工作流设计者，我想在清除下拉选择时把该输出解绑（回到默认未绑定状态），以便撤销一次绑定而不留下悬空引用。
8. 作为工作流设计者，我想让未绑定的输出保持"未绑定"这一默认状态、不自动生成任何引用，以便未配置的节点产出不会意外落到某个持久位置。
9. 作为工作流设计者，我想在重新打开面板时看到已绑定输出回显出对应变量名，以便一眼确认当前绑定到了哪个变量。
10. 作为工作流设计者，我想让回显是按内存块引用标识反查变量得到的，以便绑定按标识对齐、而非按名称。
11. 作为工作流设计者，我想在某输出的标识匹配不到任何现有变量时看到"未绑定"占位、且底层标识不被擅自清除，以便历史/异常数据如实呈现、只有我主动重选才覆盖。
12. 作为工作流设计者，我想在重命名一个已被输出绑定的变量后，绑定依然有效且回显自动跟随新名字，以便改名不破坏既有绑定（标识稳定）。
13. 作为工作流设计者，我想在删除一个被输出引用的变量后，该输出显示为悬空/未绑定而不是报错崩溃，以便前端不做级联清理、把合法性判定交给后端画布校验。
14. 作为工作流设计者，我想让多个输出、多个节点可以绑定到同一个变量，以便前端不强加唯一性限制、由后端说了算。
15. 作为工作流设计者，我想让带专用表单的节点（如 HTTP 请求）也显示输出区块，以便输出配置与输入表单形态无关、一律可见。
16. 作为工作流设计者，我想让循环节点（`For` / `ForEach`）的 `currentValue` 输出可被绑定，以便把每轮迭代值落入变量。
17. 作为工作流设计者，我想让带结果的活动（`result` 输出）可被绑定，以便通用产出也能落库到变量。
18. 作为工作流设计者，我想让没有任何可浏览输出的节点完全不显示输出区块（不留空标题），以便面板保持干净、无噪声。
19. 作为工作流设计者，我想让输出行的标题用描述符的显示名（回退到名称）、说明用 tooltip 呈现，以便获得与输入区一致的可读性。
20. 作为工作流设计者，我想让每一次绑定/解绑都进入撤销栈，以便用 undo/redo 回退输出配置。
21. 作为工作流设计者，我想让绑定/解绑后自动触发一次防抖的画布校验，以便及时看到后端对绑定合法性的反馈。
22. 作为工作流查看者，我想在只读的历史版本画布上看到输出区块但下拉被禁用，以便查看既有绑定却不会误改冻结版本。
23. 作为工作流设计者，我想让输出下拉复用与输入变量选择器一致的 `Select` 样式，以便交互与观感统一。
24. 作为开发者，我想让输出解析、绑定值构造、id→变量反查这些逻辑落在纯函数里，以便在既有测试缝上断言外部行为、不依赖 Vue 渲染。
25. 作为开发者，我想让描述符查询表（`descriptorByType`）在既有的输入之外补上输出，以便复用同一份已加载的活动描述符、不额外请求后端。

## Implementation Decisions

**改动的模块**

- **设计器状态（`useWorkflowDesigner`）**：`descriptorByType` 查询表与 `loadPalette` 目前只保留活动描述符的 `inputs`，丢弃了 `outputs`。本次让其一并捕获 `outputs`（`Array<OutputDescriptor>`）。这是纯附加的管道改动，不新增后端请求（复用已加载的 activity-descriptors）。
- **表单纯逻辑（`form.ts`）**：新增输出侧的解析与绑定辅助函数，与既有 `resolveInputFields` 对称。
- **新组件 `OutputsSection.vue`**：渲染输出行 + 变量下拉，处理 id↔name 反查与提交。
- **`NodePropertyPanel.vue`**：在输入区/专用表单下方挂载 `OutputsSection`。

**输出字段解析（`resolveOutputFields`）**

- 仿 `resolveInputFields`：对每个输出描述符，用候选名 `[clrName, name]` 经 `lowerFirst` 在活动实例上找到对应字段；找不到则跳过。
- 按 `isBrowsable !== false` 过滤；无可浏览输出时返回空列表，区块整体不渲染。
- 每个解析项形如：`{ field, label, description, output }`，其中 `label` 取 `displayName ?? name ?? field`，`output` 是当前的输出形状值或 `null`。

**绑定契约与输出生命周期**

- 输出字段默认 `null`（未绑定），不自动实例化。
- 选中变量 → 把该字段写为输出形状的普通对象：`{ memoryBlockReference: { id: <variableId> } }`。
- 清除选择 → 把该字段写回 `null`（解绑）。
- 写入一律通过既有的 `makeEditPropertyCommand(activity, field, from, to)` 提交，进 undo 栈并触发防抖的画布校验；不新增命令类型。
- 输出形状值经既有 `serializeValue` 递归序列化，无需改动序列化逻辑。

**回显与悬空处理**

- 打开时按 `output.memoryBlockReference.id` 在 `designer.variables` 里反查变量以回显其 `name`。
- 匹配不到（变量已删除、或草稿带历史 id）→ 下拉显示"未绑定"占位，**保留底层 id 不动**；只有用户主动重选才覆盖。

**改名 / 删除联动**

- 变量改名只改 `name`、保留 `id`（见既有 `renameReference`），故按 id 绑定的输出自动跟随、**无需级联**——这与输入按 name 引用需要 `cascadeRename` 形成对照。
- 变量删除**不级联清理**引用它的输出；悬空与否交后端画布校验判定（ADR 0002 后端为规则唯一真源）。

**其它**

- 数据源只限工作流变量（`designer.variables`）。
- 允许多输出 / 多节点绑定同一变量，前端不做唯一性限制。
- `designer.readonly`（历史版本）时下拉禁用。
- 输出区块独立于专用/通用表单渲染（输出与输入正交）。
- **术语文档**：`CONTEXT.md` 已收录「输出」「输出绑定」，本特性是其实现，无术语改动；**不写 ADR**——唯一 surprising 的「输出按 id 绑定 vs 输入按 name 引用」已被术语表「输出绑定」条目解释清楚，其余（区块落点、悬空显示）均为可逆的实现选择，不满足 ADR「难以逆转」门槛。

## Testing Decisions

- **好测试的标准**：只在纯函数缝上断言外部行为，不测 Vue 渲染/CSS/局部状态等实现细节。
- **主缝（`form.test.ts`，纯函数）**：
  - `resolveOutputFields` 把 `clrName` 映射为 `lowerFirst` 字段名、跳过活动上不存在的描述符、过滤 `isBrowsable=false`，并暴露当前输出形状值或 `null`。
  - 绑定值构造：给定 variableId 产出 `{ memoryBlockReference: { id } }`；清除产出 `null`。
  - id→变量反查：命中返回对应变量；悬空 id 返回空（供 UI 显示"未绑定"占位）。
- **次缝（`useWorkflowDesigner.test.ts`，既有 mock）**：断言 `descriptorByType` 现在从被 mock 的 activity-descriptors 端点带上 `outputs`。Prior art：文件顶部的 `getDescriptors` mock 与 `Load_PopulatesOutputsAndOutcomes` 用例。
- **命令写入**：复用既有 `makeEditPropertyCommand`，已被 `commands.test.ts` 覆盖，无需新增命令测试。
- **Vue 组件**（`OutputsSection.vue` / `NodePropertyPanel.vue`）：本项目无任何 `.vue` 单测，按约定不做组件级单测；在 5173 dev server 上人工走查——(a) 绑定/解绑写值正确；(b) 重开面板按 id 回显变量名；(c) 悬空 id 显示"未绑定"且不清除底层 id；(d) 变量改名后绑定仍在、回显跟随新名；(e) 只读态下拉禁用；(f) 带专用表单的节点（HTTP 请求）也显示输出区块；(g) 无可浏览输出的节点不显示区块；(h) undo/redo 可回退绑定。
- **Prior art**：`form.test.ts`（`resolveInputFields`）、`useWorkflowDesigner.test.ts`、`commands.test.ts`、`rename.test.ts`（级联语义的对照）。

## Out of Scope

- 把输出绑定到工作流输入 / 工作流输出（本期只限变量）。
- 任何后端 / 活动描述符（ActivityDescriptor）/ 序列化契约改动。
- 变量删除时对悬空输出绑定的级联清理。
- 输出绑定的前端校验规则（后端为规则唯一真源，ADR 0002）。
- 编辑输出的数据类型或表达式（输出不含表达式，方向与输入相反）。
- 在画布节点上内联展示/编辑输出（本期只在属性面板）。
- 一个输出绑定多个目标（术语表约定：一个输出同一时刻至多绑定一个目标）。

## Further Notes

- **对称性说明**：输入按 **name** 引用变量（`Expression`，改名需 `cascadeRename`）；输出按 **id** 绑定变量（`MemoryBlockReference`，改名安全）。这一不对称是刻意设计，已由 `CONTEXT.md`「输出绑定」条目记录，非缺陷。
- `descriptorByType` 此前一直丢弃 `outputs`，本特性是第一个消费者；管道改动为纯附加、低风险、可轻易回退。
- 输出默认 `null`，绑定是唯一的写入路径；未绑定即术语表所述"产出值不落入任何持久位置"的默认状态。

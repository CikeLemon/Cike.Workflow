#23 — 完善工作流实例列表功能

## What to build

给实例列表加行内"取消"动作，让用户能终止一个卡住或不该继续的运行态实例。独立可演示。

范围：
- 仅**运行态**（Pending/Executing/Suspended，即主状态 Running）行显示可用的"取消"按钮；已终态（Finished/Cancelled/Faulted/Interrupted）行禁用或隐藏，避免"点了也没用"的误导。
- 取消**不可撤销** → 用 `AlertDialog`（已在仓库）二次确认，文案点明"取消后无法恢复"。（符合项目约定：仅"有撤销兜底"的破坏性操作才免确认。）
- 后端取消为**异步、幂等**（非运行态静默忽略）、实例不存在返回 400、返回时状态尚未变更。提交成功后**不做乐观改状态**：行进入"取消中…"临时态，随后**重查当前页**让真实状态回归；失败则用轻横幅提示（仓库无 toast 基础设施，用 `actionError` 横幅替代，不引入新依赖）。
- 本期**不做批量取消**（后端只有单 id 端点）。

关键代码（决策承载，源自原型）：

取消门控 + 异步不乐观改状态：

```ts
// Pending=0 Executing=1 Suspended=2 为 Running 主状态成员
export const RUNNING_STATUSES = [0, 1, 2] as const
export function canCancel(s?: WorkflowStatus | null) {
  return s != null && (RUNNING_STATUSES as readonly number[]).includes(s)
}

async function cancel(id: string) {
  actionError.value = null
  cancellingIds.value = new Set(cancellingIds.value).add(id) // 行显示"取消中…"
  const { error } = await postApiV1WorkflowInstancesCancelById({ path: { id } })
  const next = new Set(cancellingIds.value); next.delete(id); cancellingIds.value = next
  if (error) { actionError.value = extractApiErrorMessage(error, "取消失败，请稍后重试"); return false }
  await fetch() // 重查本页拿真实状态，不本地乐观翻转
  return true
}
```

# 连接线上插入节点（Edge Insertion）

Status: ready-for-agent

> 已发布为 GitHub issue：[CikeLemon/Cike.Workflow#28](https://github.com/CikeLemon/Cike.Workflow/issues/28)，标签 `ready-for-agent`；本文件为本地工作副本。

> 本规格由一轮逐题设计访谈（grilling）收敛而来，术语遵循 `CONTEXT.md`（连接 / 插入节点），语义取舍受 ADR 0013（连接线上插入节点：首出口重接 + 按需下游移位 + 单步撤销）约束，NodeId 计算受 ADR 0003 约束。

## Problem Statement

设计器里调整流程时，最常见的结构修改是"在两个既有步骤之间补一步"：今天只能先从活动面板把节点加到画布空处，再手动删掉原连接、画两条新连接，空隙不够时还要逐个拖动下游节点腾位。操作链长、易错（忘删旧连接会留下绕过新节点的旁路），且把"想着流程"的编辑节奏打断成一连串画布杂务。

## Solution

给连接线本身加插入 affordance：可编辑模式下悬停真实连线，边中点出现圆形插入按钮；点击弹出浮动菜单（复用活动面板的分组与图标，过滤掉无入口/无出口的 Start 与 End）；选定类型后由模型层一次完成「删旧连接 → 加节点 → 按首出口规则重接 → 按需下游移位腾位」，并合并为单一撤销步；插入后新节点被选中、右侧 dock 切到节点属性，可立即配置参数。只读模式与链式容器的视觉边不提供该入口。

## User Stories

1. 作为工作流开发者，我想在两个节点之间的连接线上看到插入入口，以便我不必记住"先加节点、再删连、再重连"的手工组合。
2. 作为工作流开发者，我想插入按钮只在我悬停连线时出现，以便画布在平时保持干净、不被按钮铺满。
3. 作为工作流开发者，我想插入按钮位于连线中点，以便我的视线与鼠标移动距离最短。
4. 作为工作流开发者，我想连线的悬停热区比可见细线更宽，以便我不必瞄准 1.5px 的线才能触发按钮。
5. 作为工作流开发者，我想点击插入按钮不会选中该连线、也不会触发画布平移，以便按钮的行为纯粹、不带来副作用。
6. 作为工作流开发者，我想菜单打开期间插入按钮保持可见，以便我在选类型时仍有视觉锚点。
7. 作为工作流开发者，我想浮动菜单在按钮位置弹出，以便我的视线不需要移动到别处。
8. 作为工作流开发者，我想菜单复用活动面板的分组与图标，以便我不必学习第二套类型词表。
9. 作为工作流开发者，我想菜单过滤掉 Start 与 End，以便我不会选到插进边中间必然非法的类型。
10. 作为工作流开发者，我想菜单过高时内部滚动，以便小视口下也能选到全部类型。
11. 作为工作流开发者，我想菜单靠近视口边缘时自动翻转，以便它不被裁切到点不到。
12. 作为工作流开发者，我想按 Esc 或点空白能关闭菜单取消插入，以便我有反悔路径。
13. 作为工作流开发者，我想选中类型后立即完成插入，以便整个动作一次成型、不需要二次确认。
14. 作为工作流开发者，我想插入后原连接被移除，以便不会留下绕过新节点的旁路。
15. 作为工作流开发者，我想「源 → 新节点」的连接保留原源端口，以便分支语义（如 If 的 True）不被插入悄悄改写。
16. 作为工作流开发者，我想「新节点 → 原目标」的连接走新节点的首个出口，以便重接结果由节点自身端口声明唯一预测。
17. 作为工作流开发者，我想插入多出口节点后其余出口悬空时由画布校验与问题清单明确告知，以便我知道哪些分支尚待设计（这是预期行为而非 bug）。
18. 作为工作流开发者，我想新节点落在两端之间的中点，以便插入位置符合"插在中间"的视觉直觉。
19. 作为工作流开发者，我想两端空隙足够时其他节点一律不动，以便我的既有手工布局零扰动。
20. 作为工作流开发者，我想空隙不足时原目标的结构下游整体右移腾出刚好够的空隙，以便我不必手工拖节点让位。
21. 作为工作流开发者，我想回环路径上的节点不被裹挟进移位，以便循环结构不被插入拆散。
22. 作为工作流开发者，我想不在下游的无关分支保持原位，以便移位集合与"被插队"的直觉一致。
23. 作为工作流开发者，我想一次 Ctrl+Z 完整撤销插入（连线、节点与所有被移位置），以便这个动作的试错成本为零。
24. 作为工作流开发者，我想一次重做能完整恢复插入，以便 undo/redo 对称可信。
25. 作为工作流开发者，我想插入后新节点被选中且右侧 dock 切到节点属性，以便我立即配置它的参数。
26. 作为工作流开发者，我想下钻进的每一层容器画布的连接线都有同样的插入入口，以便内层编辑不降级。
27. 作为工作流开发者，我想只读模式（历史版本 / 实例轨迹）的连接线不出现插入按钮，以便查看态不暗示可编辑。
28. 作为工作流开发者，我想链式容器的视觉虚线边不出现插入按钮，以便该类画布不暗示它不支持的连接编辑。
29. 作为工作流开发者，我想插入节点的 NodeId 按结构路径规则计算，以便与后端物化算法一致（ADR 0003）。
30. 作为工作流开发者，我想插入结果能照常保存、发布并受既有校验闸门约束，以便新动作不绕过任何既有约束。
31. 作为维护者，我想插入语义的全部取舍记录在 ADR 0013 与术语表，以便后来者知道"插入 If 会立刻报校验错"是设计而非缺陷。

## Implementation Decisions

- **画布层**：DesignerCanvas 增加边悬停检测与边中点插入按钮（X6 edge tool 实现），并以透明宽描边命中路径扩大细线热区；按钮点击不产生边选中、不触发平移；菜单打开期间按钮保持可见；仅可编辑模式、仅真实连线渲染（视觉边与只读模式不渲染）。
- **浮动菜单**：新增业务组件（PascalCase、独立文件），复用 composable 暴露的过滤后分组；分组小标题 + 带图标类型行；max-height 超限滚动；锚定按钮屏幕坐标并自动翻转避免溢出视口；Esc / 点空白 / 选中类型均关闭。
- **composable 对外面**：`useWorkflowDesigner` 新增 `insertNodeOnConnection({ source, sourcePort?, target }, typeName): boolean` 与过滤后的插入候选分组（既有入口又有出口，Start/End 自然被排除）。连接身份用**端点三元组**而非投影 edge id——edge id 含 connections 数组下标，编辑后会漂移，不能作身份。
- **模型层**：core/designer 新增纯插入计划模块——结构下游 = 删旧边后旧图上自原目标出发的可达集，环保护 = 排除能回流到源的节点；按需移位量 = 目标空隙（新节点宽 + 2×40px 边距）− 现有空隙，空隙足够则为 0；新节点位置 = 移位后源/目标中心连线中点。commands.ts 以 `makeBatchCommand` 合成复合命令（删旧连 + 加节点 + 两条连接 + 逐节点移位且记录各自 from）；移位一律把位置物化写回 metadata，撤销时对原无保存位置的节点回到 clear。
- **规则来源**：重接与移位规则遵循 ADR 0013；NodeId 遵循 ADR 0003；零后端改动、零序列化格式改动、零校验规则改动。
- **选中语义**：插入后 `selectedActivityId` = 新节点、`selectedEdgeId` 清空，复用 `addNode` 的选中语义与右侧 dock 自动切换。
- **双重保险**：链式容器（chainChildren）与只读模式下 `insertNodeOnConnection` 直接返回 false；画布层在这些场景本就不渲染按钮。
- **样式**：按钮与菜单颜色一律走主题变量（`bg-card` / `border` / `muted-foreground` / `primary`），禁止硬编码色值。

## Testing Decisions

- 好测试只断言外部行为：connections 数组、节点 metadata 位置、selectedActivityId、undo/redo 结果；不断言 X6 内部对象与组件 DOM。
- **单一缝**：`useWorkflowDesigner` composable，扩展 `useWorkflowDesigner.test.ts`；先例为该文件与 `commands.test.ts`、`designer.test.ts`（后者含环图 fixture 构造可参照）。
- 覆盖清单：重接三件事（旧连删除 / 源端口保留 / 首出口接原目标）；候选分组过滤 Start/End；空隙足够零移动；空隙不足的移位量与移位集合（含环保护场景）；位置物化与撤销 clear；单步 undo/redo；插入后选中；链式容器与只读拒绝；非法连接标识 no-op。
- 纯插入计划函数不另开缝，经 composable 缝的可观测位置间接覆盖。
- 画布层视觉交互（悬停按钮、命中热区、菜单翻转、点按钮不误选边）：仓库无 Vue 组件测试先例，走人工验证清单 + `pnpm build`（vue-tsc）类型闸门。

## Out of Scope

- 链式容器视觉边的插入/重排（该类画布顺序由属性面板管理）。
- 全局自动重排入口与下游递归布局优化。
- 连线删除/选中交互的改造（维持点击选中 + Delete 删除现状）。
- 菜单内类型搜索框。
- 触摸设备的插入入口（悬停依赖；未来可以选中边工具条形态补）。
- 后端校验规则与任何后端契约改动。

## Further Notes

- 语义真源：ADR 0013；术语：CONTEXT.md「连接（Connection）」「插入节点（Edge Insertion）」。
- 已接受的后果：插入多出口节点（If / Switch / Decision）时其余出口悬空，画布校验立刻报"缺少连线"类问题、问题清单自动展开、节点打错误标记——设计预期行为，不做补偿连边、不弹额外提示。
- 预计改动 300–400 行：DesignerCanvas.vue、新浮动菜单组件、useWorkflowDesigner.ts、commands.ts、core/designer 新纯模块与对应测试；低于 ~500 行拆分线。
